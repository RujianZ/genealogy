```

data/
  people.json          ← 主数据。2,233 条有单独一条的人，7.4 MB
                          带 kin[] 的妻／女／无条目的子，装载时展开成 5,065 个唯一 id
  genealogy.db         ← SQLite，同样内容 + 边表 + 别名表，方便你自己查
  人工判定.json         ← 逐案回谱面核定的父子关系，每条都写着依据和核对了哪几页
  同一个人.json         ← 兼祧的人谱上印了好几条，这里记明是同一位
  02b_查无父名条目.csv   ← 179 条，父名在谱中查无此条目
  02c_多条父边的人.csv   ← 876 人，含全部候选（**题面**，不是答案）
parser/
  *.py                 ← 第一段解析器源码，能重跑
  jsonl/               ← 四册无损提取的原始 JSONL
  README-解析器.md
assets/
  cover.webp           ← 卷首红底封面，做加载页用
  shantu/*.webp        ← 16 幅手绘山图
```

## 三件事需要你自己补

1. **手机端的"我是谁"选择器**需要一份房支列表——从 `people.json` 的
   `src.section` 字段直接聚合即可（学义公世系、学仁公世系、朝寿公世系…）
2. **字体**：思源宋体 / Noto Serif SC，自己下
3. **图标**：可以从 `cover.webp` 里那个黑底黄边的族徽抠

## 写代码前先读这个

**`CLAUDE.md` 第〇节**——这是一个数据库，唯一 id ＋ 外键。
任何地方指到人都是 pid，不是名字；判定只在写 json 的时候做，页面只读不判。

**`CLAUDE.md` 第三节**是字段契约。两件事要分清：

| | 字段 | 谁写的 | 界面读不读 |
|---|---|---|---|
| 题面 | `parent_candidates`（带 `rank`／`evidence`） | 解析器给的候选 | **不读** |
| 答案 | `parent_edges`（带 `level`／`why`，每条一个 pid） | 判定层写回 | **读这个** |

## 数据还会更新

解析器还在改（未归属原文继续往字段里收、附记之人补生卒格子、功名／法名开字段）。
`people.json` 会有新版本，**字段只加不删、不改语义**。
每次改完必须 `node tools/check.mjs` 九组全过。
