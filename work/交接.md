## 二、这一轮（09-04 → 09-05）做了什么

按重要性排，每一条都是用户当场提出、当场返工的：

### 1. 卡片从渲染路径里把判定全部拆出来 ★最重要

用户原话：

> 「网站上的一切东西，包括卡片，都必须用 id 和 json 文件来渲染，不能做任何推算。
> **如果网站上有错，那一定是 json 错了，一定是我们记错了，这是数据层的问题。**」

`entries.ts` 里凡是拿名字配人的都删了。卡片现在**只做外键查找**：
`idx.get(e.parent)`、`children[]`、`adoptions[]`。
「谱上有两个，不知道是哪一个」这类话一句也不是判定层算出来的（两个生父 0、说不清 0），
全是渲染时配不准写的搪塞话——**字符串是病根**。

### 2. 父边正反两边都记

> 「A TO B 要记，B to A 也要记，他们是同等效力的，哪怕族谱上只是单向验证，
> 但我们的 json 文件不能这么记。」

`writeback.mjs` 现在同时写子那边的 `parent_edges` 和父那边的 `children`，
`fk` 闸盯着两边严格互为镜像（2,425 对）。反向边只从 canonical 记录建，兼祧不重复。

### 3. 不许有死代码

> 「我不接受任何死代码，哪怕是人工审核的那些！**而且哪怕那些是人工审核的，
> 也该是在 json 文件里我们写进去的！**」

三张写死在 TS 里的字表（`variants.ts` 1,983 行、`typos.ts`、同音组）搬进
`data/字表.json`，每条带依据。`norm.ts` 改成 `loadTables()` 装载。
`nohardcode` 闸扫 33 个文件、2,362 个字符串，比对 3,614 个谱上的名字，**放行 0 处**。

### 4. 卡片保真做成闸

新增 `tools/cardcheck.mjs`（第十组闸）：全量对 5,050 张卡片和它们在 json 里的记载。
判据统一到 `src/core/oncard.ts` **一处**——以前 audit100 一套、cardgap 一套，
同一份数据两个答案（40 条 vs 76 条）。
另有 `tools/spot20.mjs <seed> <n>` 做真随机三方对照（json / 卡片 / 谱面原文）。

### 5. 修谱名目和序作者接到 pid

`tools/revlink.mjs`。判据次序、年代闸、辈字闸见 memory 的 `zupu-revlink-titles`。
**最有用的一条：头衔常常是最硬的钥匙。** 张成祥（2016 编校）就是靠
「省教研会员」全谱只出现两次定下来的——真正的人是承武@册4 p50，字成祥，
不是那位同名、已殁于 1994 的。

### 6. 解析层把原文继续收回字段

未归属原文 2,823 → 1,195 行。引导词的七种写法、缺记声明、嫁女行、
名单里孩子的生卒葬，全部落到字段。细节见 memory 的 `zupu-parser-field-recovery`。

### 7. 字表只留一张（09-05，交接前清点时发现）

`data/variants.json`（Python 读）和 `data/字表.json`（TS 读）是同一张 948 条的表。
内容当时逐字相同，但生成脚本写的是前者 ＋ 已删掉的 `variants.ts`——再跑一次就漂。
改成 `build_variants.py` 只写 `字表.json`，四个读者全读它，
`onlynew` 反过来盯着 `variants.json` 不许再出现。

## 三、下一步：app

**这是唯一剩下的大块。** `prototype/index.html` ＋ `app.js` 是全部界面，
原生 DOM，零依赖。规矩在 `CLAUDE.md` 第六节，这里只补做的顺序。

### 桌面端 —— 三栏高密度研究工具

```
┌ 搜索框（名/字/讳/号，模糊，结果不截断）
├ 左栏：直系上溯链（27→1，一屏装得下）
├ 中栏：当前人物全字段 + 出处 + [查看原文]
└ 右栏：同辈 / 子女 / 配偶 / 反向引用
```

每行可点，点了换焦点。**必须显示 `parent_edges[].level` 和 `.why`**——
「定式」和「版面/房支对不上」要一眼看得出来，那不是谱的原话。

### 手机端 —— 给长辈的另一套布局，不是缩小版

**长辈打不了字。**繁体、生僻字（銑、硺、澐、彛）、拼音输入法，每样都是墙。

1. 第一次打开：**分级选择「我是谁」，不打字**（选房 → 选辈 → 点人），选完记住
2. 主界面是一条从自己往上的竖链，上下滑，点任意一环换焦点。手势只有滑和点
3. 搜索是备用，不是主功能
4. **关系计算器**——选两个人算该叫什么。纯算法，过年时全家会围着看

字大、行疏、一屏少信息。同一份数据两套布局。

### 视觉

加载页用封面红底龙凤图淡出，**只出现一次**。取色从封面采样正红＋宣纸米色＋墨黑。
思源宋体 / Noto Serif SC。**别竖排、别做全族树状图、别加水墨动效。**
用户明确讨厌圆角、大留白、字少的通用 AI dashboard 风格。

### 壳

桌面 Tauri（**不要 Electron**），手机 PWA（最好的安装方式是不用安装）。

## 四、数据层还欠的（都不挡 app）

**要开字段，不是加规则：**

1. 功名／学历／职业（「初中生」「郡文学生」「武汉大学」，95 行）没有字段
2. 法名（「法名履贞」）没有字段
3. 兄弟姐妹栏里 289 条其实是他自己的另一条记载（兼祧印了几条）——
   搜索那一层早就 `canonical` 折回了，兄弟栏没走同一套
4. 光福出现在他自己的兄弟姐妹名单里（自包含），要排掉

**判据太软、不该再加规则的：**

- `cardgap` 剩的 22 条（日期行 15 · 嫁女行 6 · 其他 1）——**该走 `work/谱面勘误.md` 人工过**
- `work/名目待核.json` 44 条、`work/序作者待核.json` 7 条——每条都写着为什么落不了

**一个命名隐患（还没动）：**

`data/genealogy.db` 的 `edge` 表有 3,979 行，带 `evidence`／`rank` 列——
那是**解析层的候选（题面）**，不是答案（`parent_edges` 是 2,499 条）。
表名叫 `edge` 会让人以为它是答案。没有任何代码读这个 .db，它只是给人用 SQL 查的导出。
**要么把表改名 `candidate`（改 `parser/build.py`，得重跑解析），要么删掉。**
留着不管的话，下次谁打开它就会得到错的答案。

### 十组闸

```
verify_all   数据不变量：原文一字不动、指向都存在、三条原则、世系走得通
smoke        界面走不走得通：搜索、点开、树、关系计算、译文、疑点
noloss       有没有把真的关系弄丢（父↔子双向对，只认 id）
idcheck      指到人的地方是不是全走了唯一 id——连写在别处的 pid 也查
samepid      同一个 id 有没有既占生父栏又占嗣父栏
onlynew      有没有地方能绕过新系统（可选参数、兜底、旧路、第二张字表）
nowaffle     界面上有没有「有两个同名，不知道是哪一个」这类含糊话
fk           parent_edges 每条都指向真实 pid；生父不超一位；正反两边互为镜像
cardcheck    卡片上印的 ⟷ json 里记的，5,050 张全量对
nohardcode   判据里有没有针对某个具体的人写死
```

**pid 写死之后卡片只读，一个错的 pid 和一个对的 pid 在页面上长得一模一样。
闸不是可选项，是这套架构的价钱。**

### 查原件

```bash

python tools/read_doc.py 图墓公先焕    # 按标题读卷首某一篇的全文
```

看 `page.py` 才是看谱，看 `people.json` 是看我们对谱的理解。

## 七、最后

用户的父亲是律师，看东西的方式是「这个结论的依据在哪」。
**「可追溯」这一条比任何视觉设计都值钱**，做 app 的时候不要为了好看牺牲它。

这部谱十届三百零六年，历代序里反复写着同一句准则：

> **不缘情而增，不故意而减** ／ **纪其所可知，阙其所未知**

前十届写下这句话的人只能靠自律。**这一环它是能被验证的**——闸跑一遍就出数字。
这就是这个项目的全部意义。
