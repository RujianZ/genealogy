# 人工核对记录

台账里「需要人看」的每一条，逐案回谱面核。
**结论分三种**：`自动判定正确` / `已改正（写进 data/人工判定.json）` / `谱确实没写`。

核对方式：`python tools/page.py 册N 页码` 看原始谱面（不是转译过的），
`node --experimental-strip-types tools/batchcase.mjs 名字` 摊开候选与依据。

## 一、生子名单辈字印错（4 例，同一处）

### 上彥（19世，册2·卷三·梦林公世系·第221页·第4行）

**谱面**：p223 行4 印「生子四／泽荣／泽富／泽贵／泽德／抱士宇三子铣高为子」。
上彥是 19 世，儿子应是 20 世「铣」字辈，名单却写「泽」字辈（21 世）。

**回谱面查到**：20 世那一格里，四个人各自写着自己的行次——

| 谱上原话 | 页 |
|---|---|
| 铣荣「士彥**长**子」 | 册2 p221 行5 |
| 铣富「士彥**三**子」 | 册2 p224 行5 |
| 铣贵「士彥**四**子」 | 册2 p227 行5 |
| 铣德「士彥**幼**子」 | 册2 p230 行5 |
| 铣高「士彥**养**子」字腾高**行二** | 册2 p223 行5 |

名单顺序 荣·富·贵·德 与行次 长·三·四·幼 一一对应（行二是养子铣高，不在「生子四」里）；
上彥自己那一条也写着「抱士宇三子铣高为子」，两头对上。

**结论：自动判定正确。** 四人的父边都已按各自的「士彥X子」连到上彥。
名单里那四个「泽」字是**谱面这一处辈字印错**——原文照录不动，不改。

## 二、「立嗣语句说的是同名的另一位」（19 例）

判定层遇到一句立嗣语句点了本人的名字，但核出那句说的是**同名的另一位**，於是没采信。
逐条机检两头原文：**16 例**本人写的父名与判定一致、且那位父亲的生子名单里确有他（双记 rank 1，全谱最硬）；
另 **3 例**（继华@p361/p362、开发@p48）本人写的是**嗣父**名，生父由出嗣句给出——兼祧的正常写法。

**结论：19 例自动判定全部正确。** 那条「矛盾」是判定层的说明，不是谱自己前后不一致，
台账口径应当把它从「有冲突」里挪出来。

## 八、梁元一簇（4 位同名）——一个字的判据缺口

谱把话说全了，是我们没读全：

| 梁元 | 谱上写的 | 正解 |
|---|---|---|
| 册3 p166 字明富 | 「泽翥三子」，泽翥名单第 3 位是他 | 生父泽翥，**无嗣父** |
| 册3 p253 字心藏 | 「泽成之子」，泽成名单有他 | 生父泽成，**无嗣父** |
| 册3 p259 字有业 | 「泽醕公嗣子」；泽醕写「立**三兄泽雅之子**梁元为嗣」，泽雅名单正是［梁元］ | **生父泽雅**，嗣父泽醕 |
| 册3 p311 字汉延 | 「泽沣嗣子」；泽沣写「立**三弟泽𬇕长子**梁元为嗣」 | 生父泽𬇕，嗣父泽沣 |

**原因**：抽「本生父名」的那条判据只认「X**某**子」（长/次/三…），不认「X**之**子」。
於是泽醕那句抽不出本生父，被按名字扭到了全部四个梁元头上。
字表里加一个「之」字，四个人当场各归其位。
