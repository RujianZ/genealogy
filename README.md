# 张氏宗谱 · 胜二户

湖北黄梅《张氏宗谱》胜二户，2016 年第十届续修，全四册 1,314 页。
上溯到南宋宝庆丁亥（1227）迁梅始祖张胜二，到今天二十七世，跨 772 年。

把这部谱做成一个**能查、能追到原文**的网页。

```bash
node tools/check.mjs      # 十组闸，全过才能发
node tools/bundle.mjs     # 打成单个 HTML
```

产出 `build/张氏宗谱.html`——一个文件，双击就能看，不用装东西、不用联网。

---

## 这是一个数据库

**唯一 id ＋ 外键串联的 schema。** 谱里出现过的每一个人，一行，一个 id——
男女一样，妻、女、夭折没留名的儿子都是一等公民。
任何地方指到人，指的都是 **pid**，不是名字。

```
P-{册}-{页:04d}-{行}-{列}-L{源行号}      同一行几个人加 .1 .2
```

**判定只发生在写 json 的时候，不发生在画卡片的时候。**
题面（谱的原话）和答案（一个 pid）分两格；卡片只读答案。
渲染路径里一处拿字符串配人都不许有——所有「谱上有两个，不知道是哪一个」
这类含糊话，都是渲染时配不准写的搪塞话，不是判定层的结论。

细节见 [CLAUDE.md](CLAUDE.md) 第〇节。

## 三条规矩

出自这部谱自己的凡例和历届序：

> **不缘情而增，不故意而减**　　乾隆四十一年（1776）古岩国茂
> **纪其所可知，阙其所未知**　　道光五年（1825）默齐拔萃

**不猜**　候选不止一个就全部列出来，绝不替谱做决定。
但**判不出来就不判**——把谱的原话平摆着，不写评语。

**不漏**　搜索结果一条不截。低分的排在后面，但一定列出来。
判不出来的也一条不藏，全在「谱上没说清的」那一页和 `work/` 的待核清单里。

**可追溯**　每一页底部固定显示**册几·卷几·第几页·第几行**，
点开就是谱上那一段的原文，一个字没改。

## 目录

```
source/     2016 年那一届的 Word 原件和封面照片。**这是唯一的原始材料。**
              合一/合二/合三 是三册世系正文（打字录入），
              张氏谱首（一）.doc 248 页是扫描图片
parser/     解析器（Python）：把 Word → jsonl → 字段。jsonl/ 是四册无损提取
data/       解析＋判定的产物。people.json 由 tools/writeback.mjs 写回答案，可重跑
src/core/   判定与显示（TypeScript，Node 自带类型擦除，零依赖）
prototype/  界面（index.html + app.js）
tools/      解析链、判定写回、十组闸、打包、查原件
work/       待核清单、勘误、台账、通读记录，都可重新生成
build/      成品 HTML，可重新生成
assets/     卷首红底封面 + 16 幅手绘山图
```

## 跑一遍全链

```bash
python -m parser.build parser/jsonl build/新      # 解析
cp build/新/people.json data/people.json
python tools/build_prose.py && python tools/classify_prose.py
cp data/prose.json data/prose_ents.json
python tools/extract_entities.py && python tools/attribute_prose.py
python tools/build_burials.py && python tools/build_places.py
node tools/writeback.mjs      # ★ 父子边：题面 → 答案（写 pid）
node tools/revlink.mjs        # ★ 修谱名目 + 序作者：名字 → 答案（写 pid）
node tools/relations.mjs      # ★ 人际关系表：14 类关系全写进 json，每条带对方 id
node tools/check.mjs          # ★ 十组闸，必须全过
node tools/bundle.mjs
```

## 十组闸

```
verify_all   数据不变量：原文一字不动、指向都存在、三条原则、世系走得通
smoke        界面走不走得通：搜索、点开、树、关系计算、译文、疑点
noloss       有没有把真的关系弄丢（父↔子双向对，只认 id）
idcheck      指到人的地方是不是全走了唯一 id——**一处靠名字都不行**，
             连写在别处的 pid（修谱名目）也查
samepid      同一个 id 有没有既占生父栏又占嗣父栏
onlynew      有没有地方能绕过新系统（可选参数、兜底、旧路、第二张字表）
nowaffle     界面上有没有「有两个同名，不知道是哪一个」这类含糊话
fk           parent_edges 每条都指向真实 pid；生父不超一位；**正反两边互为镜像**
cardcheck    卡片上印的 ⟷ json 里记的，5,050 张全量对——**卡片只读不判**
nohardcode   判据里有没有针对某个具体的人写死——**有就不算函数了**
```

pid 写死之后卡片只读，**一个错的 pid 和一个对的 pid 在页面上长得一模一样**。
所以这十组闸不是可选项，是这套架构的价钱。

## 查原件

```bash
python tools/page.py 册4 258          # 把谱的原始一页按表格摊开，不经过任何解析
python tools/read_doc.py 图墓公先焕    # 按标题读卷首某一篇的全文
```

看 `page.py` 才是看谱，看 `people.json` 是看我们对谱的理解。
数据里看不出的东西，翻原件往往一眼就看见——「粱四」那个排版误字、
「继发／和／才」共用辈字的写法，都是这么查出来的。

## 不做的事

年号／农历转公历、向量检索、后端服务器、登录账号、任何形式的商业化与埋点。
不改写、不清洗、不「修正」任何原文字段——谱上写「光绪二十六年月日时缺」，
那个「缺」是当年编谱人写下的「这里没有记录」，原样显示。

**「不知道」是一等值，不是空白。** 判不出来就不判，但不判也要留痕，
不然「阙」就变成了「看不见」。

**这部谱从 1710 年首修到 2016 年，十届，306 年。**
1992 年那届重修时，全族手上只剩四个人藏的十二本残卷，中间断了 118 年。
有人在谱上写下：

> 因社会变更，旧谱难以保存，间断一百廿余年，后世无法记忆先祖字号……
> **如有错误，谨请先祖赦罪。**

他们不是不想留白，是**没有地方把不确定单独记下来**，只能硬接一条。
这个项目做的是同一件事的第十一环——把那个地方给出来。
